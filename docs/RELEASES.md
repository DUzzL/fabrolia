# Release versions and artifacts

`gradle.properties` is the source of truth. The current version is `3.1.0-alpha`.
Fabric and NeoForge metadata use that SemVer form; the requested Fabric filename
is `fabrolia-alpha_3.1.0.jar`. The Minecraft target stays separately at 26.3.
The nested API retains its independent version (1.0.4).

| Change | Metadata | Fabric filename |
| --- | --- | --- |
| Initial release | `3.0.0-alpha` | `fabrolia-alpha_3.0.0.jar` |
| Bugfix | `3.0.1-alpha` | `fabrolia-alpha_3.0.1.jar` |
| Minor release | `3.1.0-alpha` | `fabrolia-alpha_3.1.0.jar` |

A minor release increments the middle number and resets the last number to zero.
A bugfix increments only the last number. Do not bump the version for each build
attempt. Update the changelog when preparing a release.

```bash
python3 tools/release/release_version.py show
python3 tools/release/release_version.py patch --dry-run
python3 tools/release/release_version.py patch       # next bugfix
python3 tools/release/release_version.py minor       # next minor, patch resets to 0
```

Build with Java 25, then check the exact artifact:

```bash
bash gradlew :common:test :fabric:build :neoforge:build
python3 tools/release/check_jar.py fabric/build/libs/fabrolia-alpha_3.1.0.jar
```

The filenames are generated by `buildSrc/src/main/groovy/fabrolia-release.gradle`;
Java settings are shared in `fabrolia-java.gradle`. The Fabric build binds its
architecture checks to the exact archive. Both loaders' upload tasks reference
their current jar task, rather than choosing a file from an old build directory.
Building or checking does not upload, tag, commit or install a release.

For runtime changes, follow [the stand checks](STAND.md) before delivering the jar.
Threading and performance changes also require matched baseline/candidate profiles.
On macOS, disable Linux CPU pinning with `FABROLIA_STAND_SERVER_CPUS=''` and
`FABROLIA_STAND_CLIENT_CPUS=''`; the stand's `flock` command also needs a local
implementation. Finder metadata is excluded from input manifests.
Install with the server stopped: remove the previous Fabrolia jar, put the new one
in `mods/`, then start. Do not leave two Fabrolia jars installed; the mod id remains
`fabrolia`, so configuration and dependencies continue to use the same identity.
